# Security Policy

## TradeWithMe Global – Security Policy

At TradeWithMe Global, we take the security of our platform, users, and information seriously. We appreciate responsible security researchers who help us identify and report vulnerabilities.

## Supported Versions

Security updates are provided for actively maintained versions of the platform.

| Version | Supported |
|---|---|
| Latest stable release | :white_check_mark: |
| Previous stable release | :white_check_mark: (where maintained) |
| Older releases | :x: |
| Development and experimental versions | :x: |

We strongly recommend that all users run the latest stable version of TradeWithMe Global.

## Reporting a Vulnerability

If you discover a security vulnerability in TradeWithMe Global, please report it responsibly.

**Preferred reporting method:**

1. Visit our GitHub repository.
2. Navigate to the Security section.
3. Use the Private Vulnerability Reporting feature, if enabled.
4. Provide a clear description of the vulnerability and steps to reproduce it.

Repository: https://github.com/wilcotrillions/tradewithme-global

Please do not publicly disclose security vulnerabilities before our team has had an opportunity to investigate and address them.

### What to Include in Your Report

Please provide:

- A description of the security vulnerability.
- Steps to reproduce the issue.
- Potential security impact.
- Screenshots or proof-of-concept evidence, where appropriate.
- Any recommended mitigation or solution.

### Response Timeline

We aim to:

- Acknowledge vulnerability reports within 5 business days.
- Provide an initial assessment within 10 business days.
- Share progress updates at least every 30 days while an issue remains unresolved.
- Work toward resolving confirmed vulnerabilities as quickly as reasonably possible.

### What Happens After Reporting?

**If the vulnerability is accepted:**
- Our development team will investigate and prioritize the issue.
- Appropriate security fixes will be developed and tested.
- A security update will be released when appropriate.
- The reporter may receive acknowledgment, subject to their preference.

**If the vulnerability is declined:**
- We will provide an explanation where possible.
- The report may be closed if the issue is not reproducible, is outside the project's security scope, or does not represent a security vulnerability.

## Responsible Disclosure

We ask security researchers to:

- Avoid accessing, modifying, or deleting other users' data.
- Avoid disrupting platform services.
- Avoid exploiting vulnerabilities beyond what is necessary to demonstrate the issue.
- Keep vulnerability details confidential until an appropriate resolution is available.

## Security Areas

We particularly welcome responsible reports involving:

- Authentication and account security.
- Login and registration vulnerabilities.
- Password reset and account recovery.
- Database security and data exposure.
- API security and access control.
- Session management.
- Cloudflare Workers and deployment security.
- Unauthorized access to user dashboards.
- Protection of personal and financial information.
